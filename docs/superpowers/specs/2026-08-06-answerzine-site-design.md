## 1. 배경

저장소에는 주간 제작 파이프라인(문서 5종, 에이전트 5종, `tools/qa.mjs`, 빌더, 대시보드, CI)이 갖춰져 있다.

| PC 레이아웃 | 1440px에서 본문이 쓰는 폭 680px (47%). 640px 위 브레이크포인트 0개 |

`CLAUDE.md` §9의 결함 기록 13건은 전부 재현됐다. 그중 P0 5건은 **주간 생산이 시작되면 매주 악화되는** 종류다.

문제의 뿌리는 하나다. **콘텐츠 정본이 두 곳(`issues/*.json`과 HTML)에 있고, 두 번째 정본을 사람이 손으로 옮겨 적는다.**

## 3. 아키텍처

```
issues/*.json          ─┐
domains/registry.json  ─┤
sources/whitelist.json ─┼─►  build/build.mjs  ─►  dist/
assets/ (폰트·로고·사진) ─┘     (Node 내장 모듈만, 의존성 0)
```

### 3.1 산출물 구조

```
dist/
  index.html                아카이브 인덱스 (최신 호 리드 + 지난 호 목록)
  2026-w31/index.html       회차 페이지 — QR이 가리키는 주소
  2026-w31/book/index.html  개별 스토리
  2026-w31/print/index.html A4 인쇄 진
  assets/fonts/*.woff2
  assets/img/*
  404.html
```

디렉터리 + `index.html` 방식이라 **GitHub Pages에서 서버 설정 없이 `/2026-w31/`이 그대로 열린다.**
`location.hash` 라우터가 필요 없고, 회차별 OG 태그를 정적으로 심을 수 있다.

### 3.2 빌드 스크립트의 책임

`build/build.mjs`는 순수 함수 파이프라인이다.

1. `issues/*.json` 전량 로드 → `range` 기준 **시간순 정렬** (§9.2·§9.5의 원인 제거)
2. `registry.json`에서 도메인 메타·분량 예산 로드
3. 스토리 → HTML 렌더 (`escapeHTML()` 필수 경유 — §9.7)
4. 회차 → 인쇄 진 렌더 (`renderZinePage()`, 리드 1 + 미니 3)
5. 정적 파일 기록

**템플릿은 문자열 결합이지 프레임워크가 아니다.** 모든 사용자 문자열은 `escapeHTML()`을 통과한다.
`onclick` 문자열 보간을 쓰지 않고 이벤트 위임으로 처리한다.

### 3.3 실행

```bash
node build/build.mjs            # dist/ 생성
node build/build.mjs --serve    # 로컬 미리보기 (node:http, 의존성 0)
node tools/qa.mjs               # 기존 검증
node build/verify.mjs           # 신규 — 빌드 산출물 검증 (§12)
```

## 4. 데이터 계약 변경

기존 필드는 전부 유지한다. 아래만 추가한다. **전부 선택 필드라 기존 회차가 그대로 통과한다.**

| 필드 | 타입 | 용도 |
|---|---|---|
| `zineBody` | `string[]` | 인쇄 진 본문 축약 3문단. 없으면 `blocks[0]`·`[2]`·`[4]`를 잘라 자동 생성 |
| `photo` | `{ src, alt, credit? }` | 리드 사진. 없으면 기존 사선 스트라이프 플레이스홀더 |
| `issue.lead` | `string` | 리드 스토리의 `id`. 없으면 `stories[0]` |

`headline`·`teaser`는 **웹과 인쇄가 같은 값을 참조**한다. 별도 저장하지 않으므로 §8 QA #17(문자열 일치)이 **구조적으로 위반 불가능**해진다.

## 5. 디자인 시스템

### 5.1 세 테마 — 같은 역할 토큰, 세 벌의 값

`design.md` §1이 이미 "역할 이름은 두 테마에서 같고 값만 다르다"로 설계해둔 구조를 세 벌로 확장한다.

| | Night (기본) | Paper (대체) | Zine (인쇄) |
|---|---|---|---|
| 적용 | `:root` | `[data-theme="paper"]` | `.zine-page` / `@media print` |
| 배경 | `#16150F` | `#F4F1E7` | `#F4F1E7` |
| `--ink` | `#F2EFE4` (15.89:1) | `#17150F` (16.15:1) | `#17150F` |
| `--secondary` | `#A8A192` (7.12:1) | `#5C574A` (6.37:1) | `#5C574A` |
| `--tertiary` | `#8A8375` (4.86:1) | `#726C5E` (4.62:1) | `#726C5E` |

대비는 전부 WCAG 2.1로 계산한 실측값이다. **세 역할 모두 AA(4.5:1)를 넘긴다** — 기존 `--tertiary` `#8E8E93`(4.88:1)이 아슬아슬했던 것을 여유 있게 끌어올렸다.

Night는 중성 회색 `#222222`이 아니라 **따뜻한 먹빛 `#16150F`**다. 같은 크림 지면을 밤에 뒤집어 보는 인상이라 Paper와 한 세계로 묶인다.
`--secondary`·`--tertiary`는 중성 회색이 아니라 배경 색상에서 뽑은 갈회색이다 — impeccable `craft-floor.md`의 *"tint secondary text from that hue or the foreground; never gray"*.

### 5.2 테마 전환

- 기본값은 **Night**다. `prefers-color-scheme: light`로 자동 전환하지 **않는다.**
- 마스트헤드의 토글로 Paper로 바꿀 수 있고, 선택은 `localStorage`에 남는다.
- `@media print`는 활성 테마와 무관하게 **항상 Zine**을 강제한다.
- 인라인 스크립트로 첫 페인트 전에 `data-theme`을 적용해 깜빡임을 막는다.

> **트레이드오프:** OS 라이트 선호를 무시하는 건 브랜드 기본값을 우선한 결정이다.
> `prefers-color-scheme`를 존중하도록 바꾸려면 초기화 스크립트 한 줄만 고치면 된다.

### 5.3 도메인 컬러 — 테마별 두 벌

현재 4색은 전부 `#222222` 기준으로 고른 값이라 **크림 배경에서 무너진다.** 실측:

| 도메인 | 현재색 | `#222222` | Paper | Paper 보정색 | 보정 후 | Night `#16150F` |
|---|---|---|---|---|---|---|
| 음악 | `#FF9500` | 7.24 | **1.95** | `#A15E00` | 4.51 | **8.32** |
| 도서 | `#34C759` | 7.17 | **1.96** | `#217E38` | 4.53 | **8.24** |
| 영화 | `#0A84FF` | **4.36** | **3.23** | `#006BD7` | 4.55 | **5.01** |
| 유튜브 | `#FF2D55` | **4.36** | **3.23** | `#DD002A` | 4.52 | **5.01** |

보정색은 **hue를 한 도도 바꾸지 않고 명도만 내려** 4.5:1을 넘긴 값이다 (210°·35°·349°·135° 그대로).
`design.md` §6.2의 "색상환 거리 ≥40°" 확장 규칙과 §6.3의 열린 구간(75–95°, 250–309°)이 그대로 유효하다.

**부수 효과:** `design.md` §6.1은 영화·유튜브가 `#222222`에서 4.36:1로 AA 미달인 것을 "브랜드 자산이라 유지"한다고 기록해뒀다.
Night 배경에서는 같은 색이 **5.01:1로 통과한다.** 색을 바꾸지 않고 배경만 바꿔서 해소된다.

`registry.json`의 각 도메인에 `colorPaper` 필드를 추가한다. `color`는 Night용으로 의미가 고정된다.
Zine 테마에는 도메인 색을 쓰지 않는 기존 규칙(§6)을 유지한다.

### 5.4 타이포그래피

| 역할 | 서체 | 웨이트 |
|---|---|---|
| 헤드라인 · 킥커 · 라벨 · 수치 · UI | Paperlogy | 400 / 700 / 900 |
| 본문 · 티저 · 쿼트 | 명조 (§15 결정 대기) | 400 / 600 |

두 번째 가족을 들이는 근거는 impeccable `typeset.md`의 기준 — *"do not introduce a second family without a clear role it alone can perform"* — 을 충족한다.
**한국어 장문 가독은 명조만 하는 일이고, 수치 조판은 산세리프만 하는 일이다.** 데이터와 산문이 서로 다른 목소리를 갖는다.

교정 항목:

- **로드하지 않은 웨이트를 참조하지 않는다.** 기존 CSS의 500·590·600·800 참조를 전부 없앤다 (§9.8).
  스케일은 400/700/900 세 단만으로 재정의한다.
- **킥커에서 모노스페이스를 뺀다.** impeccable의 *"monospace as a costume for 'technical'"* 지적을 수용한다.
  산세리프 700 + 자간 0.14em + `text-transform: uppercase`로 대체한다.
- **Night 본문은 자간을 양수로 준다** (`+0.005em`). 어두운 배경의 밝은 텍스트는 자간·행간·웨이트 세 축에서 보정해야 한다는
  `craft-floor.md` 지침이고, 현재는 전 슬롯이 음수라 반대 방향이다.
- 헤드라인 자간 하한은 **−0.04em**을 넘지 않는다. 실사용은 −0.02 ~ −0.035em.
- 본문 측정(measure)은 **45–75자** 범위를 지킨다.

**킥커는 유지한다.** impeccable은 킥커를 "브리프로도 되살릴 수 없는 금지"로 두지만, 같은 문서가 *"The brief wins"*라고도 쓴다.
이 제품의 브리프는 신문 지면이고 킥커는 그 장르의 문법이다. 무엇보다 `kicker`는 `issues/*.json`·`qa.mjs`·에이전트 5종에 걸친
**데이터 스키마 필드**라, 제거는 파이프라인 전체를 건드리는 변경이다. 대신 조판(모노스페이스)만 교정한다.

### 5.5 컴포넌트 교정

| 항목 | 현재 | 변경 | 근거 |
|---|---|---|---|
| 풀쿼트 보더 | `border-left: 3px` 도메인색 | **1px** 또는 배경 대비로 대체 | craft-floor "colored border-left above 1px" |

## 6. 레이아웃

### 6.1 골격 — 인쇄 지면과 같은 구조

아카이브 인덱스는 인쇄 진의 **"리드 1 + 미니 3"**을 그대로 화면으로 옮긴다. 두 매체가 한 시각 언어를 쓰는 것이 방향 A의 핵심이다.

### 6.2 브레이크포인트

| 구간 | 구조 | 변하는 것 |
|---|---|---|
| ≥1200px | 12칼럼 · 본문 col 1–7 / 근거 레일 col 9–12 | 레일 sticky, 세로 괘선 표시 |
| 768–1199px | 8칼럼 · 본문 전폭 | 레일이 본문 흐름 안으로 내려옴, 괘선 제거 |
| <768px | 1단 | 마스트헤드 축약, 스탯이 본문 사이에 인라인 |

### 6.3 본문에 CSS 다단을 쓰지 않는다

신문이 다단인 것은 **지면이 고정돼 있기 때문**이다. 웹에서 본문을 다단으로 짜면 아래로 읽다가 다시 위로 올라와야 한다.
대신 **비대칭 그리드**로 신문의 인상을 만든다 — 본문은 45–75자 한 칼럼, 숫자와 인사이트는 오른쪽 레일에 세로 괘선으로 붙는다.

레일에 스탯이 상주하므로 **"근거는 늘 옆에 있다"는 태도가 레이아웃으로 표현된다.**
동시에 hover에 의존하던 출처 노출(§9.9)이 구조적으로 해소된다.

다단은 **인쇄 진에서만** 쓴다. 거기서는 지면이 고정이라 원래 맞는 도구다.

## 7. 인쇄 진 생성

`renderZinePage(issue)`가 `issues/*.json`에서 리드 1 + 미니 3을 생성한다. HTML 하드코딩을 없앤다 (§9.3).

- `@media print` 숨김 목록에 **`.statement-wrap`을 반드시 포함한다** (§9.1 — 현재 4페이지가 나오는 원인).
- `@page { size: A4; margin: 0 }` 유지. 안전 여백은 `.zine-page` 패딩 `8mm 10mm`가 전담한다.
- 분량 예산은 `design.md` §4의 실측표를 그대로 승계한다 (권장 1.5× / 절대상한 2.0×).
- 리드 스티커 수치는 리드 `stat.value`를 **참조**한다. 별도 입력하지 않는다.
- QR은 `answerzine.kr/YYYY-wNN`을 가리키고, 그 URL은 §3.1의 회차 페이지로 **실제로 존재하게 된다** (§9.4 해소).

## 8. 라우팅과 메타데이터

| URL | 내용 |
|---|---|
| `/` | 아카이브 인덱스. 최신 호 리드 + 지난 호 목록 + 도메인 필터 |
| `/YYYY-wNN/` | 회차 페이지 — **QR 도착지** |
| `/YYYY-wNN/<domainKey>/` | 개별 스토리 |
| `/YYYY-wNN/print/` | A4 인쇄 진 |

- 회차·스토리마다 OG 태그·`description`·canonical을 정적 생성한다 (§9.10).
- 이전/다음 내비게이션은 **`range` 정렬 배열** 위에서 인덱싱한다 (§9.2).
- 도메인 필터는 URL 쿼리(`?domain=book`)에 반영하고, **필터가 걸린 상태의 배열이 내비게이션의 단일 소스**가 된다 (§9.5).
- 파비콘을 추가한다 (현재 콘솔 에러 1건의 원인).

## 9. 에셋

- Paperlogy는 **SIL OFL**이다. 웹폰트 변환·자체 호스팅·재배포가 허용된다 — §9.6의 라이선스 확인 항목 해소.
- base64 인라인을 **전부 걷어내고** `assets/`로 분리한다. TTF → WOFF2 변환.
- 현재는 4.07MB가 **매 페이지 로드마다** 전송되고 캐시되지 않는다. 분리 후에는 한 번 받아 전 페이지에서 재사용된다.
- 로드하는 웨이트는 §5.4에 열거한 것만이다. 쓰지 않는 웨이트는 로드하지 않는다.

## 10. 접근성

- 스파크라인 SVG에 `<title>`/`aria-label`로 추세를 문장으로 제공한다 (§9.9).
- 인사이트 툴팁은 hover·focus 양쪽에서 열리고, 좁은 화면에서는 **툴팁이 아니라 펼침 블록**으로 렌더한다.
- 뷰 전환 시 포커스를 새 제목으로 이동시킨다.
- `prefers-reduced-motion: reduce`에서 애니메이션은 멈추되 콘텐츠는 보인다 (기존 규칙 유지).
- 모든 대화형 요소에 팔레트에서 뽑은 `:focus-visible` 링을 준다.

## 15. 열린 결정 — 사용자 판단 필요

### 15.1 본문 명조를 어떻게 조달할 것인가

한국어 명조는 글리프가 많아 파일이 크다. 세 선택지의 트레이드오프가 다르다.

| 안 | 전송량 | 장점 | 단점 |
|---|---|---|---|
| **A. Nanum Myeongjo 자체 호스팅** (추천) | 2웨이트 WOFF2 약 1MB | 외부 의존 0, 인쇄 신뢰성 높음, OFL | KS X 1001 2,350자 범위. 드문 음절에서 폴백 발생 가능 |
| B. Noto Serif KR 자체 호스팅 | 서브셋 없이 수 MB | 11,172자 전량 커버 | 서브셋 도구가 필요한데 npm 의존성은 §7.3 승인 사항 |
| C. Google Fonts CDN | 실사용 100–300KB | `unicode-range` 자동 서브셋, 도구 불필요 | **런타임 외부 의존.** 인쇄 시 폰트 미로딩 위험 |

A안이라도 폰트 3벌(Paperlogy) + 2벌(명조) ≈ 1.9MB이고, **한 번 받아 전 페이지에서 캐시된다.**
매 페이지 4.07MB를 캐시 없이 전송하는 현재보다 낫다.

### 15.2 저장소가 아직 git이 아니다

`git rev-parse` 결과 `not a git repository`다. `README.md` §1이 안내하는 `git init`이 아직 실행되지 않았다.
스펙·구현을 커밋하려면 먼저 초기화가 필요하다. **초기화 여부는 사용자 결정 사항이다.**

### 15.3 LESSONS.md 신규 교훈 등록

인쇄 지면에 회수된 영화 편이 남아 있던 건은 L-001(개봉일 사고)과 **다른 종류의 사고**다.
"정본이 둘이면 한쪽만 고쳐진다"는 구조적 교훈이라 별도 등록 후보다.
`AGENTS.md` §4는 에이전트가 `LESSONS.md`를 직접 고치지 않고 **제안만** 하도록 규정한다.
