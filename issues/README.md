# issues/ — 완성된 회차가 들어가는 곳

**한 주에 파일 하나입니다.** 이름은 `YYYY-wNN.json`이고, 그 주에 나간 기사가 전부 들어갑니다.

`runs/`가 **작업 과정**이라면 여기는 **결과물**입니다.

---

## 1. 파일 생김새

```json
{
  "issue": "2026-w31",
  "status": "draft",
  "range": "2026.07.28 – 08.03",
  "notes": "이번 주 편집 메모. 못 실은 카테고리와 이유를 적습니다.",
  "insight": "이번 호 4편을 관통하는 한두 문장. 독자에게 그대로 보입니다.",
  "insightPrint": "insight의 인쇄용 축약판(1줄). 없으면 인쇄 진에는 안 실립니다.",
  "stories": [ /* 점수 높은 순: 1면 → 나머지 3개 */ ]
}
```

| 항목 | 무엇인가요 |
|---|---|
| `issue` | 몇 년 몇 주차인지. 파일 이름과 같아야 합니다 |
| `status` | `draft`(작업 중) 또는 `ready`(발행 준비 완료). 아래 §2 |
| `range` | 집계한 기간. 가운데 기호는 짧은 붙임표(-)가 아니라 긴 대시(–)입니다 |
| `notes` | **못 실은 카테고리와 이유를 꼭 적습니다.** 편집자 전용 — 독자에게 절대 안 보입니다 |
| `insight` | **그 주 스토리 전체를 관통하는 통합 인사이트. `notes`와 반대로 독자에게 보입니다** — 홈 아카이브 데이트라인 아래에 실립니다. `ready` 회차는 필수입니다 |
| `insightPrint` | `insight`의 인쇄용 축약판(A4 한 줄 분량). 선택 — 없으면 인쇄 진에는 그냥 안 실립니다 |
| `stories` | 점수 순으로 정렬됩니다. 맨 앞 기사가 종이 1면을 차지합니다 |

### `insight`는 어떻게 쓰나요

각 스토리를 다 쓴 **다음**에 마지막으로 씁니다. 그 주 4편의 숫자·계기를 최소 두 개 이상 구체적으로
끌어와야 합니다 — "다들 열심히 산다" 같은 두루뭉술한 문장은 안 됩니다. §4/S2의 3조건 "이례성"
("그 도메인에서 이 시점에 기대되는 값과 다른가")을 회차 전체로 한 번 더 접는다고 생각하면 됩니다:
그 주 넷이 공통으로 **무엇을 배신했는지**를 찾습니다.

### 기사 하나의 생김새

```json
{
  "id": "2026-w31-book",
  "range": "2026.07.28 – 08.03",
  "domain": "도서",
  "market": "KR",
  "anchorDate": "2026-07-23",
  "anchorSourceUrl": "https://…",
  "kicker": "IN MEMORIAM",
  "headline": "부고 다음날, 서점이 붐볐다.",
  "teaser": "…",
  "blocks": [ /* 현상 → 숫자 → 맥락 → 해석 → 마무리, 정확히 5개 */ ]
}
```

이 중 세 개가 **날짜와 시장을 확인하는 데 쓰입니다.**

- `market` — 국내 기사면 `KR`, 해외면 `OVERSEAS`
- `anchorDate` — 그 일이 **국내에서 일어난 날**. 개봉일, 발매일, 출간일, 영상 올라온 날, 부고일
- `anchorSourceUrl` — 그 날짜를 어디서 확인했는지

카테고리별로 어떤 날짜를 써야 하는지는 `market-scope.md` §4에 정리돼 있습니다.

## 2. `draft`와 `ready`의 차이

| 값 | 검사할 때 | 언제 쓰나요 |
|---|---|---|
| `draft` | 문제가 있어도 **경고로만** 알려줍니다. 배포가 멈추지 않습니다 | 아직 작업 중일 때 |
| `ready` | 문제가 하나라도 있으면 **배포를 막습니다** | 발행 직전에 |

작업 중에 자동 검사가 계속 빨간불이 되면 불편하니까 나눠둔 것입니다.
**발행 전에는 반드시 `ready`로 바꾸고** `node tools/qa.mjs`가 통과하는지 확인하세요.
`draft`인 채로 내보내면 검사를 건너뛴 것과 같습니다.

---

## 3. 작업 순서

보통은 에이전트가 알아서 만들어줍니다. 직접 하시려면 이렇게 하시면 됩니다.

1. `tools/zine-builder.html`을 열고 카테고리별로 입력한 뒤 `이 스토리 저장`을 누릅니다
2. JSON 탭에서 `.json 다운로드`를 누릅니다
3. 받은 파일을 이 폴더에 `YYYY-wNN.json` 이름으로 올립니다
4. `node tools/qa.mjs`로 확인합니다 (또는 그냥 올리고 자동 검사에 맡기셔도 됩니다)
5. 통과하면 `status`를 `ready`로 바꾸고 저장합니다

### 영화 편을 뺀 이유

이 기사는 **국내 개봉 전 기간의 극장 데이터를 인용했습니다.**

- 본문이 쓴 개봉일 `2026-07-15`는 2025년 12월에 발표됐다가 **2026년 4월에 취소된 예정일**입니다
- 실제 국내 개봉일은 `2026-08-05`이고, 미국 개봉일은 또 `2026-07-17`로 다릅니다
- 그런데 이 회차의 집계 기간은 `2026.07.28 – 08.03` — 한국에서 아직 상영하지 않던 주간입니다
- 그래서 본문의 `4주 차 감소율 -14%`는 **애초에 계산이 불가능한 숫자**였습니다

고치려면 실제 개봉 4주 차에 해당하는 `2026-w35` 무렵에 다시 취재해야 합니다.
전말은 `market-scope.md` §2에 있고, 이제 이런 실수는 자동 검사가 잡아냅니다.
