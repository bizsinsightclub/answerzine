# runs/raw — 주간 원본 스냅숏

`tools/collect.mjs`가 매주 여기에 그 주의 원본 수치를 떠 놓는다.

```
runs/raw/2026-w32/netflix.json
runs/raw/2026-w32/yes24.json
runs/raw/2026-w32/kyobo.json
```

## 왜 필요한가

이 저장소의 출처 절반은 `snapshot`이다 — 조회 시점의 순위만 보여주고 지난 주 값은 사후에 열리지 않는다.
예스24·교보문고·멜론이 그렇다. 그래서 추세선을 그릴 수 없었다 (`LESSONS.md` L-011).

**못 그리는 진짜 이유는 아무도 아카이브를 안 해서다.**
매주 같은 방법으로 읽어서 여기에 커밋해 두면, 다음 주부터는 **우리가 그 아카이브다.**

그때부터는 스냅숏 출처에서도 선을 그릴 수 있다. 각 점이 커밋된 파일을 가리키므로 누구든 같은 값을 다시 볼 수 있기 때문이다.

```js
{ type: "stat",
  label: "주간 판매지수",
  value: "+326.5%",
  trend: [98, 101, 100, 426],
  axisCaption: "X축: 최근 4주 · Y축: 예스24 판매지수",
  trendSource: "각 주 runs/raw/*/yes24.json에서 같은 ISBN의 salesIndex를 읽었다.",
  trendSnapshots: [                       // ← 점 수와 개수가 같아야 한다
    "runs/raw/2026-w29/yes24.json",
    "runs/raw/2026-w30/yes24.json",
    "runs/raw/2026-w31/yes24.json",
    "runs/raw/2026-w32/yes24.json"
  ],
  sourceUrl: "https://www.yes24.com/24/category/bestseller" }
```

`tools/qa.mjs`가 파일 존재·개수·경로를 전부 확인한다. 없는 파일을 대면 실패한다.

## 규칙

**수집을 거른 주는 영영 복구되지 않는다.** 스냅숏 출처는 과거를 되돌려주지 않는다.
그래서 `collect.mjs`는 스냅숏 어댑터에 대해 **현재 주가 아니면 수집을 거부한다** —
오늘 값을 지난 주 파일명으로 저장하는 게 이 저장소에서 가장 위험한 거짓말이기 때문이다.

- 수집은 **매주 화요일 이후**에 돈다. 넷플릭스 TSV가 그때 갱신된다.
- 파일은 **손으로 고치지 않는다.** 그 주에 화면에 있던 값 그대로여야 의미가 있다.
  잘못 떴으면 다시 뜨고, 다시 뜰 수 없으면 지운다. 고쳐서 남기지 않는다.
- 파싱이 깨지면 `note`에 사유를 남기고 그 도메인은 그 주 결번으로 간다 (`CLAUDE.md` §7.2).

## 파일 형식

| 필드 | 뜻 |
|---|---|
| `source` | 어댑터 이름 (`netflix` · `yes24` · `kyobo` · `circlechart` · `kobis` · `kopis`) |
| `week` · `range` | ISO 주차(월~일)와 표기 |
| `collectedAt` | **언제 찍은 스냅숏인가** — 이 파일의 존재 이유 |
| `method` | `tsv` · `fetch` · `openapi` · `playwright` |
| `url` | 실제로 연 주소. 오픈API 키는 `***`로 가린다 |
| `note` | 이 출처를 읽을 때 알아야 하는 함정 |
| `rows` | 해석하지 않은 원본 행 |

## 출처별 주 경계가 다르다

같은 "31주차"라도 기관마다 기간이 다르다. **스토리의 `range`는 그 출처의 기간을 그대로 옮긴다.**

| 출처 | 주 경계 | 2026 w31 |
|---|---|---|
| ISO (이 저장소 기준) | 월~일 | 07.27 ~ 08.02 |
| 넷플릭스 | 월~일 (일요일 라벨) | 07.27 ~ 08.02 |
| 써클차트 | **일~토** | 07.26 ~ 08.01 |
| 교보문고 | 화~월 (화면 표기 확인) | 07.29 ~ 08.04 |
